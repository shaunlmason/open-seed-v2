# Plan: next Phase 6.1 — submission, verifier workspace, receipt, verdict.rendered at L1 (os-f6d2c267)

Design authority: [`SEED-NEXT.md`](../SEED-NEXT.md) Part II §8 "The verdict
pipeline" (done is a verdict and a reconciliation; independence is
failure-domain separation) and Part III.G rows 3–5 (implementer-disjoint
verdict keys; clean per-run isolation with enumerable, self-executed
inputs; receipts that bind and recompute);
[`docs/next-build-plan.md`](../docs/next-build-plan.md) Phase 6 item 1.
This card lands the verdict pipeline's first half: `verdict.rendered`
piped through admission, the clean per-run verifier workspace, and receipt
computation. The reconciliation chain and divergence drills are 6.2
(os-6cdc15be), sealed checks 6.3 (os-3128535a), red-verdict lockout and
the operator override verb 6.4 (os-d2497eb7); rubrics and L2/L3 are
Phase 10/11. The failed verdict's return path out of `review` stays the
named extension point — nothing here adds a transition.

## Design decisions (binding for this task)

1. **Packages.** `next/internal/verdict` (workspace lifecycle, visible-spec
   runner, receipt computation) and `next/internal/artifact` (a minimal
   content-addressed store: `Put`/`Get` keyed by SHA-256 hex under
   `next/var/artifacts/sha256/<digest>`, inside the already-gitignored
   `next/var/`). The build plan's git-addressed `refs/seed/artifacts`
   push is deferred (filesystem fallback first, the observation-channel
   precedent); recorded in `next/docs/decisions.md`.
2. **The event.** `verdict.rendered` deepens from free event to piped
   fact with strict payload
   `{"verdict": "pass"|"fail", "receipt": "<sha256 hex>", "submission": "<position>", "independence": "L1"}`.
   It admits only on a subject whose folded state is `review` (elsewhere
   it refuses exit 3, the illegal-verb-in-state posture); it is a fact,
   not a transition — the state stays `review`, and `done` still arrives
   only via `merge.observed` (6.2 pipes the rest of the chain).
   `submission` must equal the chain position of the `submission.made`
   that produced the current `review` state, binding the verdict to the
   submission it judges; only the literal `"L1"` admits in v0 (the level
   vocabulary widens in Phase 10, which declares levels per tier).
3. **Capability row.** New kind `verdict` (`keyring.CapVerdict`);
   `verdict.rendered` accepts `[verdict]` — deliberately **without** the
   operator fallback every other row carries: III.G row 3 says operator
   override is its own attributable verb, never a disguised verdict, and
   that verb lands in 6.4. A governance root that wants to judge holds an
   explicit `verdict` grant. `actors.md` gains the row and the rationale;
   the spec-parsing test pins it.
4. **L1 independence at admission.** The implementing-key set of a
   contract = every fingerprint that ever signed a `claim.taken` on it
   (current holder and all prior claimants, from the fold's claim facts)
   plus the signer of the bound `submission.made`. A verdict whose signer
   is in that set refuses with new exit **17 `not_independent`**, naming
   the fingerprint and its implementing role — distinct from 14
   `out_of_grant` (capability absent) because the key may hold a perfectly
   good verdict grant and still be disqualified on this contract. The
   fold records `submission {position, signer}` per contract to support
   the binding and the disjointness check; the contracts **view** is
   unchanged in 6.1 (surfacing verdicts in projections rides 6.2's
   divergence work).
5. **Workspace and sandbox.** Per-run clean checkout under a fresh
   unique temp dir via a detached **local clone with the origin remote
   removed** — not `git worktree add`, whose checkout shares the parent
   repository's refs and object store through its `.git` link, handing
   any hostile spec command `git update-ref`/`git push` reach back into
   the host repo (review finding on this plan). Parallel runs never
   collide (unique dirs drilled); cleanup fires pass or fail, drilled
   with an induced failing run. The charter's "sandbox with declared,
   minimal capability" (Part II §6) lands as a **runner capability
   profile, declared in the receipt**: v0 ships the `exec` profile —
   scrubbed environment (explicit minimal `PATH`; `HOME`, `TMPDIR`,
   `GIT_*` pointed inside the workspace; nothing inherited), no path
   back to the parent repository, a per-command wall-clock timeout with
   process-group kill — and declares `network: unrestricted` honestly,
   because portable no-root Go cannot deny the network; the runner is
   an interface so a namespaced or containerized profile slots in at
   the executor-adapter seam (build plan Phase 7 item 3, Phase 12
   hardening) without touching verdict logic, and every receipt names
   the profile it ran under. Drills: a planted secret in the invoking
   environment is invisible to spec commands; a workspace command
   attempting to update parent refs cannot reach them; a hanging
   command is killed at the timeout. The receipt is computed
   exclusively from this checkout and the ledger — packet anchors are
   used only to *name* the range; every hash is recomputed (enumerable
   inputs, no implementer-claims channel, III.G row 4).
6. **Receipt.** JCS-canonicalized JSON, digest = SHA-256 over the JCS
   bytes, stored content-addressed; the verdict cites the digest. Fields:
   `{"contract", "merge_base", "head", "plan": {"path", "sha256"}|null, "diff_sha256", "files": [...], "transcripts": [{"cmd", "exit", "output_sha256", "output_bytes"}, ...], "environment": {"os", "arch", "go"}}`.
   `merge_base`/`head` resolve from the submission packet's mandatory
   diff-vs-merge-base range anchor (5.3) to **full commit SHAs, stored
   immutably in the receipt** — a verdict attests exactly that
   `{merge_base, head, diff_sha256}` triple and nothing else; the
   verifier refuses a range whose head does not descend from its
   merge-base (shape sanity before checkout). There is deliberately no
   branch-tip check here: branches are forge state the ledger cannot
   see, so "the merge landed code other than the attested head" —
   including an implementer submitting an older clean head while a
   branch points at different code — is exactly the divergence 6.2's
   reconciliation detects by comparing `merge.observed`'s forge fact
   against the verdict's attested head (an induced drill on that card,
   cross-referenced; review finding on this plan). `plan` is the
   approved plan blob hashed **at the merge-base** (null for a planless
   trivial-tier contract); `diff_sha256` and `files` recompute from
   `git diff` in the workspace; transcripts carry the output digest and
   byte count, never inline bytes (bounded receipts; storing full
   outputs as artifacts is deferred); environment is `runtime` facts
   (GOOS, GOARCH, Go version) plus the runner capability profile.
   "Verification recomputes everything from the submission head and
   fails on mismatch" is a first-class verb, not only a test.
7. **Gate-before-run** (the half acceptance.md left to Phase 6). Before
   any command runs, the verifier reads the contract's folded acceptance:
   `executable: true` without gate evidence refuses new exit **18
   `ungated`** with nothing executed (drilled with a sentinel command
   that would leave a trace); `executable: true` whose gated body yields
   zero parseable commands refuses new exit **19 `spec_unrunnable`**
   (declared armed but empty — silence must never decide);
   `executable: false` runs nothing and the receipt carries an empty
   transcript list. Command grammar: the acceptance body's
   "validation commands" marked section, exactly the plan grammar —
   extraction is factored into an exported `plan.Commands` shared by
   lint and verifier. Exits 17/18/19 take the lowest unused integers
   per envelope.md's allocation rule; the table rows and
   `internal/envelope` constants land in this task PR with the rules
   that emit them (the exit-15/16 precedent).
8. **CLI.** Three verbs: `seed verdict receipt <subject>` (resolve the
   bound submission, build the workspace, gate check, run the visible
   spec, store the receipt, print digest + summary in the envelope);
   `seed verdict render <subject> --verdict pass|fail` (compute the
   receipt fresh, then append `verdict.rendered` through the established
   signed-append path — admission enforces capability and independence);
   **render derives the permissible verdict from the transcripts it just
   computed**: any nonzero transcript exit forbids `--verdict pass`,
   refusing with the failing command named (review finding on this
   plan) — `fail` is always renderable, and a prose-only spec (no
   transcripts) leaves pass/fail the verifier's explicit judgment. The
   enforcement seam is the render verb because the verifier is the one
   party holding the transcripts it just executed; admission cannot
   re-run commands or read a verifier-local artifact store (the
   cooperative-posture precedent: the client refuses to draft doomed
   work), and a raw-pushed pass-over-red is not silent — `seed verdict
   check` recomputes and goes red, which is 6.2 reconciliation input;
   `seed verdict check <subject>` (recompute from the submission head
   and compare against the latest rendered verdict's cited digest; a
   mismatch fails naming both digests — the Phase 6 exit's
   recompute-and-mismatch surface).
9. **Spec.** New `next/spec/verdicts.md` (normative: event shape,
   independence set, receipt schema, workspace, runner-profile, and
   gate rules, the transcript-derived render rule, conformance mapping
   to III.G); `envelope.md` rows 17/18/19;
   `actors.md` the verdict row; `lifecycle.md` updated where it calls
   `verdict.rendered` "not-yet-piped" (merge.requested stays free until
   6.2, merge.observed stays the operator-gated done transition).

## Steps

1. **Spec first.** Write `next/spec/verdicts.md`; add envelope.md rows
   17 `not_independent` / 18 `ungated` / 19 `spec_unrunnable` and the
   matching `internal/envelope` constants; add the `actors.md` verdict
   row; touch up lifecycle.md's piped-verbs sentence.
2. **Artifact store.** `internal/artifact`: content-addressed Put/Get
   with digest verification on read; tests (round-trip, corrupt-on-disk
   detected, concurrent puts of the same digest).
3. **Command extraction.** Export `plan.Commands` (the marked-section
   walk lint already does), used by lint unchanged and by the verifier;
   tests pin labeled and bare bullet forms and the empty case.
4. **Verdict core.** `internal/verdict`: workspace create/cleanup (the
   origin-stripped clone); the profiled runner (`exec` profile: scrubbed
   environment, per-command timeout with process-group kill); receipt
   computation (range resolution from the submission packet with the
   head-descends-from-merge-base refusal, plan-at-merge-base, diff +
   inventory, transcripts, environment fingerprint incl. the runner
   profile, JCS digest); gate-before-run refusals. Tests: digest
   determinism across two runs; tamper drills (edited diff, swapped
   head) fail recompute; non-descendant head refused; planless null
   plan; parallel workspaces distinct; cleanup on induced failure;
   sentinel proves ungated content never executed; a planted invoking-
   environment secret invisible to spec commands; a workspace command
   cannot update parent refs; a hanging command killed at the timeout.
5. **Fold + admission.** `internal/transition`: fold records
   `submission {position, signer}`; `internal/keyring`: `CapVerdict` +
   row; `internal/admit`: the `verdict` rule (review-state gate, strict
   shape, submission binding, L1 independence with exit 17). Drills:
   disjoint verdict-granted key admits (pass and fail verdicts); holder
   refused 17; prior claimant refused 17; submission signer refused 17;
   operator without verdict grant refused 14; verdict-granted key on a
   non-review subject refused 3; wrong submission position refused;
   fence citation refused (no active fence outside `in_progress`, the
   lifecycle.md rule, pinned).
6. **CLI.** `seed verdict receipt|render|check` with envelope output;
   render's transcript-derived verdict rule (pass over any nonzero
   transcript exit refused naming the failing command; fail always
   renderable; prose-only pass allowed as explicit judgment);
   end-to-end two-key drill (implementer takes a contract through
   specified→claimed→planned→submitted; a second, verdict-granted key
   renders pass; check green; tamper the stored receipt or range →
   check red naming both digests; a submission whose gated spec fails
   → render pass refused, render fail lands).
7. **Docs.** progress.md ledger row, decisions.md entries (artifact
   store deferral, verdict-only capability row, exit allocations,
   fold submission fact), LEARNINGS/DEADENDS if anything durable
   surfaced.

## Acceptance Criteria

**Boundary set (new, shown working):**

- `verdict.rendered` admits on a `review` subject from a
  verdict-granted, implementer-disjoint key citing the bound
  submission position; refusals drilled: 3 (not in review), 17 (holder,
  prior claimant, and submission signer each), 14 (no verdict grant,
  operator included), shape (unknown key, bad verdict value, wrong
  independence literal, wrong submission position), and a fence
  citation outside `in_progress`.
- The receipt digest is deterministic across two computations of the
  same submission; `seed verdict check` recomputes from the submission
  head and goes red naming both digests when the range, diff, or stored
  receipt is tampered; a planless trivial contract yields `plan: null`;
  transcripts record per-command exit and output digest; the
  environment fingerprint carries GOOS/GOARCH/Go version.
- Workspaces are per-run unique (two parallel runs share nothing),
  contain exactly the submission head's tree, and cleanup fires on both
  the pass path and an induced failure; the runner profile is declared
  in the receipt, spec commands see none of the invoking environment's
  secrets, cannot update the parent repository's refs, and are killed
  at the per-command timeout; a head that does not descend from its
  merge-base refuses before checkout.
- Gate-before-run: ungated executable content refuses 18 with the
  sentinel untouched; gated content runs in the workspace; prose-only
  yields an empty transcript list; declared-executable-but-empty
  refuses 19.
- The two-key end-to-end CLI drill passes: render by the second key,
  check green, tampered check red; render refuses `--verdict pass`
  over a failing transcript naming the command, renders `fail` for the
  same submission, and allows a prose-only pass as explicit judgment.

**Retention set (existing, shown unharmed):**

- Every pre-existing suite is green: `make check` (which runs
  `check-next`) passes at the coverage gate; no existing test is
  weakened, skipped, or deleted.
- Projection stamps, view schemas, and cache generation are unchanged
  by this card; `seed plan lint` behavior is unchanged by the
  `Commands` factoring.
- No v1 surface changes; the task PR never touches `plans/**`.
