## Design decisions

### D1. The mirror is a separate, projection-only component

Add a public `next/mirror` package and a separate `next/cmd/seed-mirror`
binary. `seed-mirror plan|apply` consumes a **published `contracts`
projection** plus its `projection.json` stamp; it never opens a ledger,
accepts a Seed signing key, contacts admission, or imports the request
writer. Its only write is outward through a mirror adapter to the declared
forge. The existing `seed request file` remains the separate governed
ingress component.

The canonical desired issue is intentionally small and reversible: one
issue per contract with a valid lifecycle state, title equal to the opaque
contract subject, body containing only the marker
`<!-- seed-mirror: <marker> -->` and the projection `(position, tip)`
marker, and exactly one managed `seed:<state>` label. `<marker>` is the
subject's UTF-8 bytes base64-encoded: contract subjects are opaque and
admission restricts no character, so the raw value is never embedded and no
subject can terminate or re-open the comment. Decoding is the only parse
path; a marker that does not decode to a known subject is malformed. `done` and `cancelled` are closed; every other state is
open. Foreign labels and issues without the Seed marker are untouched;
managed-state drift and an externally closed non-terminal issue are
overwritten from the projection. Duplicate or malformed Seed markers
refuse rather than choosing an authority by accident. `plan` is sorted and
byte-deterministic; applying it twice is a no-op.

GitHub and Forgejo are the two registered reference exporters. Their HTTP
differences stay behind one adapter interface; the common issue state is
the conformance contract, and a capability one forge cannot express is a
reported variance, never a silently skipped assertion. Credentials come
from forge-specific environment variables and never appear in the
projection, plan, ledger, command output, or committed fixture.

### D2. Every registered exporter runs the same conformance suite

The mirror registry is the only construction path used by `seed-mirror`.
A table-driven suite iterates the registry, so adding a usable exporter
without running the common suite is impossible. Each GitHub, Forgejo and
snapshot/fake arm is required to prove:

1. a missing marked issue is created from the stamped projection;
2. managed label, title, body, open/closed drift is restored from the
   projection while foreign labels and unrelated issues survive;
3. a matching mirror yields no action and a second apply makes no request;
4. terminal and non-terminal transitions converge to the desired external
   state;
5. an adapter failure leaves the Seed projection and ledger unchanged and
   is reported with the exporter name and failed action;
6. no exporter API exposes or invokes `request.filed`, a Seed key, a ledger
   append, or an admission endpoint;
7. a hostile subject (containing `-->`, newlines, and non-ASCII bytes)
   round-trips: the base64 marker parses back to the exact subject, and a
   malformed, truncated, or tampered marker refuses rather than repairing.

The full D.5 drill adds the ingress half rather than merely citing it: for
each registered exporter, render a contract, mutate the mirror-side state,
prove that the ledger did not move, file the edit through the existing
`request.filed` path with an enrolled standing-only service key, prove the
request is admitted and changes no lifecycle state, and rerun export to
restore the mirror from the authoritative projection. A direct attempt by
the service identity to perform a coordination verb still refuses at
admission. This proves one-way export and governed request ingress as one
scenario per exporter.

### D3. Component ownership is an import-closure property

Add `next/internal/authoritylint`, run under `go test` and therefore
`check-next`. It parses the module's production packages and executable
dependency graph. A deployable component is a `next/cmd/*` main package;
an **export path** is derived from a dependency on the sealed mirror
registry/adapters; a **coordination write path** is derived from the
ledger/admission proposal primitives and their concrete append, commit,
push and propose call sites. The sets are computed from source and package
edges rather than maintained as a claimed count.

The lint fails when one executable's transitive closure contains both
classes. It also requires every mirror adapter implementation to be sealed
in and reachable through the registry, refuses mirror packages importing a
coordination-write owner, and asserts that `seed-mirror` has no
`--ledger`, `--remote`, `--key`, `--config`-admission, or proposal flag.
The existing `seed` and `seed-admit` components may write coordination
state but may not import the mirror registry. The term **component** and
this executable-closure definition are recorded in the projection spec so
D.6 is a falsifiable structural claim rather than a naming convention.

The detector self-checks against synthetic package graphs: a clean split
passes; an exporter importing an append primitive fails; a coordination
binary importing the mirror registry fails; and an adapter hidden outside
the registry fails. The real-tree walk is the lint. Tests may assemble
both sides as fixtures but production packages may not.

### D4. External facts have one closed, governed vocabulary

Add `next/internal/externalfact` and a normative table in
`next/spec/external-facts.md`. The table inventories every protocol event
whose payload asserts a fact owned by an external system, its permitted
governed signer class, source, and allowed ledger-only consequence. It
includes the existing reviewed-merge observations (`plan.approved`,
`merge.observed`, `curation.lesson.promoted`, the externally grounded arms
of `curation.lesson.retired`, and `workflow.merged`) and the new
`check.observed`. Rows whose authority is internal (verdicts, requests,
offers, budget facts, checkpoints, artifact erasure) are explicitly outside
the table and the spec says why.

The code catalog and spec table are pinned in both directions. Every
catalogued verb must be in the protocol/affordance vocabulary, must admit
only for the table's governed capability set (`observer|operator`, or the
operator-only human gate where already required), and must be re-judged at
its own position before a consumer treats it as authentic. Conversely,
every production verb described as an external observation or accepted by
the observer capability must occur in the catalog. Existing plan approval
does **not** gain an observer fallback: the human plan gate remains
operator-only.

### D5. Implement `check.observed` as a fact, never a verdict

Complete the catalogued `check.* observed` wire path with
`check.observed` at the next protocol version. Its strict payload is
`{name, status, commit, reference}`: `name` is a token; `status` is one of
`pass|fail|cancelled`; `commit` is a full lowercase-hex commit; and
`reference` is the external run/check reference, not its log body. It is a
fact on a contract subject (or `system` for a repository-wide check),
signed by an `observer|operator`. It has no transition-table row, never
satisfies an acceptance command, never creates a verdict, never discharges
an obligation, and never makes a merge request legal. It is retained and
queryable as evidence, but is not control.

`seed check observe --forge github|forgejo|snapshot` reads the named check
from a read-only source interface and records the returned fact through the
ordinary admission path. The GitHub and Forgejo sources, plus the snapshot
fixture, are registered beside the existing merge source. Both forge
sources use GET only. An unknown, pending, missing or malformed check
refuses without an append. The new protocol version is explicit rather
than silently teaching an old version a new verb; the version drill proves
the immediately preceding version refuses it.

### D6. Observation sources cannot perform external control

Split the forge observation readers from the mutating protections adapters
behind a read-only `externalfact.Source` interface. The observation
component receives the least credential needed to read merge/check state;
the interface has no apply, merge, rerun, cancel, label, or protection
method. A source lint rejects non-GET HTTP methods, process execution, or
imports of the mirror/protections mutation owners in production source
implementations. It self-checks against a planted POST and a planted
mutator import.

The governed-observation drill runs against fake GitHub and Forgejo APIs
that record every request. It proves that observing a merged PR and a
completed check emits only GETs and then one admitted fact signed by a
properly granted identity; observing an unmerged PR or incomplete check
emits no fact; a claim-only key is refused; a raw or out-of-order merge
observation remains a reconciliation divergence rather than laundering a
verdict; and `check.observed` leaves lifecycle state, affordances,
obligations, budgets, submissions and verdicts unchanged. A planted
consumer that treats a passing check as a verdict or legalizes a merge
fails the snapshot/property drill. `merge.observed` retains only its
charter-specified ledger reconciliation effect after an independently
valid pass/override and `merge.requested`; no observation invokes the
external action it reports.

### D7. Conformance and docs close only on executable evidence

Update `next/spec/conformance.json` D.5, D.6 and D.7 from `open` to `met`,
phase `13`, only after the per-exporter suite, authority lint, external-fact
catalog pin, and governed-observation drills are green. Evidence names the
task PR and exact test functions. Regenerate
`next/docs/generated/conformance.md`; extend `next/spec/projections.md`,
`forges.md`, `protocol.md`, `actors.md`, `envelope.md` and the operator
handbook with the component boundary, mirror contract and observation
semantics. The build-plan item/exit record and frontier route the rows by
name. No charter amendment is in scope.

## Acceptance Criteria

### Boundary set (new behavior, shown working)

1. **D.5, per exporter.** GitHub and Forgejo are registered reference
   mirror exporters and every registry member passes the same suite:
   deterministic create/update/open/close planning, projection-wins drift
   repair, unrelated external state retained, second apply a no-op, and
   failures leaving Seed bytes unchanged.
2. **D.5, ingress joined to export.** For each exporter, a mirror-side edit
   cannot move the ledger; the edit enters only as an admitted
   `request.filed` signed by an enrolled standing service key, changes no
   lifecycle state, and a subsequent export restores the external mirror.
   A direct coordination act by that key refuses.
3. **D.6, structural separation.** The real-tree authority lint finds no
   executable whose dependency closure contains both mirror export and
   coordination write. `seed-mirror` has no Seed write flag or primitive;
   `seed`/`seed-admit` do not import the mirror registry. Each planted
   overlap and an unregistered adapter fail by name.
4. **D.7, governed facts.** The external-fact code catalog and normative
   table agree in both directions; every row's signer set is enforced at
   admission and every consuming derivation rechecks authenticity at the
   record's position. The existing operator-only plan gate stays
   operator-only.
5. **D.7, checks are observations.** `check.observed` admits only at the
   new protocol version for an `observer|operator`, with the strict shape;
   the prior version, an unknown status, a non-observer, a pending source
   result and a source mismatch all refuse without appending.
6. **D.7, no observation controls.** GitHub and Forgejo observation suites
   emit GET only. Merge observation never invokes a merge and authenticates
   no missing verdict/request; check observation changes no lifecycle,
   affordance, obligation, budget, submission or verdict state. The planted
   POST/import violations and passing-check-as-verdict consumer fail.
7. **The rows are owned and closed.** The build plan and frontier name
   Phase 13 item 8 and this card; conformance D.5–D.7 are `met`, phase `13`,
   with exact tests and task PR as evidence; generated conformance docs are
   byte-current and `seed doctor` no longer reports the three rows.
8. `make check` is green; the coverage gate remains at least 90%; no model
   identifiers or credentials appear in committed artifacts.
