# Plan: next Phase 3.1 — actor events and the keyring projection (os-52a2d688)

Implements [`docs/next-build-plan.md`](../docs/next-build-plan.md) Phase 3
item 1: `actor.enrolled` / `actor.granted` / `actor.suspended` /
`actor.revoked` as ledger events, and the keyring as a projection over the
chain prefix. Design authority: [`SEED-NEXT.md`](../SEED-NEXT.md) Part II
"Enrollment" and "Capabilities" (enrollment carries the public key, an
*asserted* kind, and a display name; revocation ends standing while the
key's history stays attributed) and the verb catalog in
[`next/spec/protocol.md`](../next/spec/protocol.md) (`actor.*`).
Conformance: III.E "every actor is a keypair; enrollment, grants,
suspension, revocation are events; the keyring is a projection; admission
verifies signatures on every proposal" (the events + projection half:
grant *checking* is Phase 3.2, the revocation drill is 3.3,
`actor.qualified` and tuples are Phase 10).

## Steps

1. **The keyring package.** `next/internal/keyring`: standing state
   (per-fingerprint: active / suspended / revoked, plus accumulated grant
   strings as data for 3.2) seeded from the genesis payload's root keys,
   with one transition function `Advance(record)` owning the actor-event
   contract — strict payload shapes (`enrolled`: raw 32-byte Ed25519 key
   as 64 hex chars, `kind` one of human/agent/service, display `name`,
   and the event subject equal to the key's fingerprint; `granted`:
   capability string; `suspended`/`revoked`: reason) and transition
   legality (enrolling an already-active key refuses; re-enrolling a
   suspended key reinstates it; revocation is terminal, so enrolling or
   suspending a revoked key refuses; granted/suspended/revoked require an
   enrolled subject; and suspending or revoking a governance root that
   would leave zero active roots refuses — root liveness: the keyring
   must never transition into a state admission cannot recover from, and
   root rotation beyond that guard is genesis-level governance, out of
   scope here). `StateAt(records)` replays a prefix;
   `Resolver()` exposes the standing-aware
   fingerprint-to-key map for the tip. One transition function, two
   consumers (verification and admission), per the shared-rule-set
   requirement.
2. **Position-aware verification behind a `seed/1` activation
   boundary.** The keyring semantics are a validation-rule change a
   conformant `seed/0` validator would judge differently, so per the
   bump discipline in `next/spec/protocol.md` they activate at protocol
   version **`seed/1`**: `ledger.VerifyFromGenesis` advances the keyring
   as it replays, and for records at positions where the active version
   is `seed/1`, each signature resolves against the standing *as of that
   position* — a key signs only between its enrollment and its
   suspension/revocation, while history signed before a standing change
   keeps verifying (attribution preserved, the charter's revocation
   semantics) — and a malformed or illegal actor event fails
   verification at its position (the upgrade-schema discipline: a signed
   but broken enrollment must not wedge readers silently later).
   Records at `seed/0` positions are grandfathered: an `actor.*` event
   there is inert (no keyring effect, no new judgment), so any chain
   that verified before this change still verifies. The supported set
   gains `seed/1`; the existing `Resolver` parameter stays the root-key
   seam (genesis bootstrap unchanged).
3. **Admission.** `admit.Context` carries the keyring standing at the
   tip: the `actor` rule resolves signers through it, and a new
   `standing` rule applies `keyring.Advance` to actor-verb drafts before
   they are admitted plus an interim authorization check: until 3.2's
   grant machinery, `actor.*` verbs are accepted only from the governance
   root (recorded as a decision; 3.2 replaces it with grant-checked
   operator rights). An `actor.*` draft at a tip whose active version is
   still `seed/0` refuses as a verb illegal in this state (exit 3: the
   semantics are not active until the deployment upgrades). The
   authorization refusal is a new condition the
   charter names (out-of-grant), not a verification failure: allocate
   **exit 14 `out_of_grant`** per the envelope spec's lowest-unused rule
   — table row, `next/internal/envelope` constant, and spec-mirror test
   land here, before any code emits it. Hook and cooperative client
   construction sites pick the keyring up; the hook's per-record
   exclusion set is unchanged (standing is replay-owned, like actor and
   version).
4. **Spec.** `next/spec/actors.md`: the four payload schemas, standing
   transitions (root liveness included), and the charter's
   kind-is-an-assertion language ("an assertion by the enrolling
   operator, not a cryptographic fact"). `next/spec/protocol.md` records
   the `seed/1` bump per its own discipline — what a `seed/0` validator
   judges differently, and the grandfathering of `seed/0` positions —
   and its catalog line points at `actors.md`.
5. **Tests** (library, ledger, hook, CLI): enrollment round-trip on an
   upgraded chain (root upgrades to `seed/1`, enrolls a key, the key
   signs later records, from-genesis verification green);
   pre-enrollment and post-revocation signatures refuse at their
   positions; suspension pauses standing and re-enrollment reinstates;
   revocation is terminal; revoking or suspending the last active
   governance root refuses (root liveness); a chain carrying an
   `actor.*` record at a `seed/0` position verifies unchanged
   (grandfathered) with enforcement starting after
   `system.protocol.upgraded`; an `actor.*` draft at a `seed/0` tip
   refuses as an illegal verb; malformed enrollment at a `seed/1`
   position fails verification there; raw-pushed enrollment chains
   through the `seed-admit` hook admit and refuse identically (one rule
   set);
   non-root `actor.*` drafts refuse at exit 14 with the envelope
   constant pinned by the spec-mirror test; CLI append of an actor event
   end-to-end.

## Acceptance Criteria

**Boundary set (new, shown working):**

- An enrolled key's events verify from genesis on a `seed/1` chain; the
  same events refuse when signed before enrollment, while suspended, or
  after revocation — and records signed before the standing change keep
  verifying (history stays attributed).
- A chain that verified before this change still verifies: `actor.*`
  records at `seed/0` positions are inert, keyring semantics activate
  only from the `seed/1` boundary (the protocol.md bump discipline,
  followed to the letter), and an `actor.*` draft at a `seed/0` tip
  refuses as an illegal verb.
- The last active governance root cannot be suspended or revoked
  (refusal shown working), so no admitted transition can leave the
  deployment without a key that admission accepts `actor.*` from.
- Revocation is terminal: re-enrolling or suspending a revoked
  fingerprint refuses; re-enrolling a suspended fingerprint reinstates.
- Verification and admission share one transition function: the hook
  refuses exactly what a cooperative client refuses for actor events.
- Non-root `actor.*` drafts refuse at the newly allocated exit 14
  `out_of_grant` (documented in the spec table before any code emits
  it); grant payloads accumulate as data for 3.2.
- A malformed actor event in history fails verification at its position.

**Retention set (existing, shown unharmed):**

- All existing verb suites pass unchanged
  (`cd next && go test ./internal/... ./cmd/... -count=1`).
- The repo-wide gate stays green with the ≥90% coverage gate
  (`make check`).
