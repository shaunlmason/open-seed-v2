# Plan: next Phase 7.4 — graceful preemption (os-0f718b4e)

Implements `docs/next-build-plan.md` Phase 7 item 4: graceful
preemption — safe-point interrupt → park with packet; force path →
reap packet. Design authority: SEED-NEXT.md §II.9 ("**Preemption** is
graceful-first: interrupt at a safe point → park with packet;
force-kill is the fallback and still yields a reap packet. Safe-point
semantics (the executor checks for interrupts at bounded intervals
and exits deliberately) are part of the worker contract, because
reaping a live worker and B-style timeout fallbacks presuppose
them"), charter III.H's preemption row ("Preemption is graceful-first
with specified safe-point semantics in the worker contract;
force-kill still yields a reap packet"), and the machinery already
landed: `claim.parked` (in_progress → blocked, claim lane) and
`claim.reaped` (in_progress → ready, dispatch/operator lanes) each
refuse without a shape-valid four-part packet
(`next/spec/packets.md` — "the reaper writes the reap packet from
what is known, so a force-kill still yields one"), and the 7.3 spend
bracket (reserve, `run.started`, Provision, meter, `run.settled`)
fences every execution run. What 7.4 adds is the missing first half:
an attributable interrupt REQUEST the worker can observe, the
safe-point semantics that make observing it a contract, and the two
drills. B-style automatic timeout reaping is Phase 9's maintenance
loop; this task drills the manual force path it presupposes.

## Design decisions (binding for this task)

- **D1 — the interrupt request is a ledger fact.** New verb
  `run.interrupted`, strict payload `{"fence": "<position>"}`,
  admitted only while the subject is `in_progress` and the cited
  fence is the ACTIVE claim fence, from {supervise, operator} (the
  lanes that manage runs, matching `run.started`). The ledger is the
  coordination medium and polling is the liveness floor the 7.1
  wakeless drill proved, so the canonical interrupt channel is the
  chain itself: no marker files, no adapter side-channels in v0 (an
  adapter MAY later accelerate delivery the way wake accelerates
  scheduling — advisory only, correctness never depends on it).
  `run.interrupted` is NOT a spending verb: preemption is
  supervisory control and must not be budget-gated (a subject whose
  budget is exhausted is precisely one a supervisor may need to
  interrupt).
- **D2 — the fold records interrupts as independent facts.**
  `SubjectState.Interrupts []InterruptFact{Pos, Signer, Fence}`,
  folded tolerantly in the run-fact posture: a fact citing a fence
  that is no applied claim position counts an anomaly, never a fact;
  a duplicate same-fence interrupt counts an anomaly AND stays
  visible; nothing is mutated. Admission refuses a second interrupt
  per fence gated on boundary validity (a raw invalid interrupt
  neither blocks the legitimate supervisor's nor is one), the
  one-per-fence posture `run.started` established.
- **D3 — position-accurate validity, shared, from the start.**
  `admit.InterruptValid(records, table, subject, st)`: the signer
  held an accepted lane at the fact's own position and the cited
  fence was the ACTIVE claim fence there — every check against
  `records[:st.Pos]` (the RunStartValid lesson: fold presence is
  never proof of admission, and a consumer that trusts it launders
  raw pushes into authority). `admit.InterruptRequested(records,
  table, subject, s, fence) bool` is the one derivation workers and
  drills share: whether any boundary-valid interrupt stands for the
  fence. The security shape this closes is denial-of-service by raw
  push: an unprivileged raw `run.interrupted` must neither park a
  worker (workers poll only boundary-valid interrupts) nor block or
  satisfy anything at admission.
- **D4 — safe-point semantics are the worker contract, specified in
  the spec.** `next/spec/executors.md` gains a Preemption section:
  a conforming worker checks `InterruptRequested` for its active
  fence at bounded intervals (at least once per metering/poll
  cycle; the interval is the worker's declared sync cadence), and on
  observing one finishes its current step (the safe point), writes
  its four-part packet, and exits `in_progress` deliberately via
  `claim.parked` — park, not release: preemption is the
  supervisor's "stop now", and `blocked` hands routing back to the
  dispatch lane (`contract.unblocked` → ready → next claim), which
  the graceful drill exercises end to end. The adapter interface is
  untouched: the check is the worker's, not the adapter's, exactly
  as the charter locates it, so `next/executor`'s public surface
  does not change in this task.
- **D5 — the force path yields a reap packet from what is known.**
  When a worker ignores its interrupt, the fallback is the 7.3
  disposability posture: SIGKILL, then `claim.reaped` by the
  dispatch or operator lane carrying an honest four-part packet
  composed from what the reaper can know — acceptance from the
  contract's specified criteria, `base` as the zero-length range
  when no pushed work is known, `refs` possibly empty, `findings`
  recording the interrupt that was ignored and the kill. The
  existing packet rule already enforces the shape; the drill proves
  the flow: reaped → ready, immediately re-claimable, the chain
  verifies, and the contract completes elsewhere from the surviving
  ledger alone. `run.settled` still records the dead run's actuals
  afterward (7.3 designed prior-fence settles for exactly this).
- **D6 — projections carry the new fact additively.** Contracts
  version "12": per-subject `interrupts` (position, signer, fence),
  omitempty so interrupt-free chains keep byte-identical version-11
  bodies (pinned by the untouched goldens). Report version "9"
  (republish). Cache schema generation 11: an `interrupts` table
  (subject, position, signer, fence). Version-pin tests bump beside
  each (the established cadence).

## Steps

1. **Transition + fold**: `RunInterruptedVerb = "run.interrupted"`
   beside the run verbs (fence-rule-exempt for the same reason:
   its fence field is a window reference the interrupt rule
   validates); `InterruptFact` + `SubjectState.Interrupts`; fold
   branch in the run-fact posture (dangling fence = anomaly;
   same-fence duplicate = anomaly + append). Fold test beside
   `TestRunFactFold`.
2. **Keyring**: `run.interrupted` → {CapSupervise, CapOperator} row
   + completeness-test row.
3. **Admission**: extend the run rule (it already owns the run-fact
   family): strict `{fence}` decode, `in_progress` only, fence ==
   ACTIVE claim fence, once per fence gated on `InterruptValid`.
   Export `InterruptValid` and `InterruptRequested` beside
   `RunStartValid`, every citation judged against
   `records[:st.Pos]`.
4. **Spec**: `next/spec/executors.md` Preemption section (D4, D5:
   the interrupt fact, bounded-interval checks, deliberate exit via
   `claim.parked`, the force path and its reap packet);
   `next/spec/actors.md` one row; one linking sentence in
   `next/spec/lifecycle.md` beside the parked/reaped exits.
5. **Projections**: contracts "12" + goldens, report "9", cache
   generation 11 + `interrupts` table; version-pin tests.
6. **Graceful drill** (`next/cmd/seed`, the 7.3 fixtures): full
   bracket (claim, reserve, `run.started`, Provision), helper
   worker variant polling `InterruptRequested` each cycle; a raw
   worker-signed interrupt first — the worker ignores it (D3's DoS
   shape) and admission refuses nothing for it; then the
   supervisor's admitted interrupt; the worker parks deliberately
   (`claim.parked` + packet, exit 0, never killed); assert blocked
   + packet visible, `contract.unblocked` → ready → a second
   claim completes the contract elsewhere; `run.settled` records
   the parked run.
7. **Force drill**: same bracket, worker variant that never polls;
   supervisor's interrupt admitted; worker still metering past a
   deadline (proves it ignored it); SIGKILL; `claim.reaped` by the
   operator root with the D5 packet; assert ready, chain verifies,
   re-claim + completion elsewhere, post-reap `run.settled`,
   Dispose loses nothing admitted.
8. **Docs**: decision-log entry; progress rows + frontier
   (`next/docs/progress.md`).

## Acceptance Criteria

1. `run.interrupted` admits only in_progress, on the active fence,
   from {supervise, operator}, once per fence; strict payload;
   refusals name their reasons.
2. A raw-pushed interrupt is fold-visible with an anomaly, blocks
   nothing at admission, satisfies nothing, and — via the shared
   boundary-valid filter — parks no conforming worker.
3. The graceful drill: a polling worker observes the admitted
   interrupt at a safe point and exits deliberately via
   `claim.parked` with a shape-valid packet; the contract is
   unblocked, re-claimed, and completes elsewhere; the chain
   verifies throughout.
4. The force drill: a non-polling worker is SIGKILLed after
   ignoring its interrupt; `claim.reaped` lands with an honest
   packet from what is known; the subject returns to ready,
   is re-claimed, and completes elsewhere; `run.settled` records
   the dead run; disposal loses nothing admitted.
5. Projections: contracts "12" with omitempty interrupts
   (interrupt-free bodies byte-identical to "11", goldens
   untouched), report "9", cache generation 11; version pins
   updated.
6. `make check` green from the repo root with cleaned caches;
   coverage at or above the 90% gate.
