## Design decisions (binding for this task)

**D1. The table is a checked-in file, one row per charter row,
verbatim.** `next/spec/conformance.json`: `{"pillars": [{"id": "A",
"title": "The Ledger", "rows": [{"row": 1, "text": "<the charter's
row, whitespace-normalized>", "status": "met", "posture":
"any|enforced-only", "phase": "1", "evidence": "<PRs and test names>",
"note": "<the routing or residual, when PARTIAL or routed>"}]}]}`.
The status vocabulary is exactly `met`, `partial`, `routed`, `open`,
with `partial` and `routed` each requiring a non-empty `note` naming
where the rest lives, and `met` requiring non-empty `evidence`. The
posture is read off the row's `(*enforced-only*)` marker at clause
level: a marker opening the row makes the row `enforced-only`,
judged at the enforced postures alone; a marker inside the row
qualifies one clause among others that hold everywhere (III.A row 4's
remote refusal beside its universal mutation detection, III.L row 5's
admission-only ledger writes beside its other protections), and the
row is `mixed`, judged at every posture and named at the cooperative
one. Refused: a row the charter does not have, a charter row the
table lacks, a text that differs from the charter's after whitespace
normalization, a status outside the vocabulary, a numeric weight or
score of any kind.

**D2. The drill parses the charter.** `internal/conformance` (new)
parses `SEED-NEXT.md`'s Part III into pillars and rows (the `### <L>.
<title>` headings, the `- [ ]` rows with their continuation lines) and
`TestTableIsTheCharterRowForRow` holds `conformance.json` to it in both
directions, so the table cannot drift from the charter and the
charter cannot grow a row the table does not judge. The same package
loads and validates the table (`Load`, `Validate`) for the two
consumers below.

**D3. The docs generator renders it.** `seed docs generate` writes
`next/docs/generated/conformance.md`: a summary line per pillar (rows
met, partial, routed, open) and, per pillar, a table of rows with
status, phase and evidence, the note in a trailing column; `docs
check` gates it like the others. The rendering carries no date and no
clock: the table is the source, the exit records the evidence.

**D4. The doctor reports it.** `seed doctor` gains `conformance`:
`{"met", "partial", "routed", "open"}` counts over the rows judged at
the declared posture; `"outstanding_rows"` listing every row not
`met` as `<pillar>.<row>` with its status, phase and note (`open`,
`partial` and `routed` alike: the charter admits a conformance claim
only when every criterion holds, so a partial or routed row is
outstanding, never quietly complete), which is the "which Phase 13
criteria remain open" the build plan asks for; `"complete"` true
exactly when every judged row is `met` at an enforced posture. A
cooperative deployment reports the enforced-only rows as
`not_applicable_here`, the documentation the charter's Part III
preamble requires of it, the mixed rows under `mixed_here`, and
`complete: false` with the sentence saying why. Reads the table from
the source tree (`--repo`, default the working directory) like `docs`
does, never a ledger.

**D5. The statuses are the exit records', not this card's
judgment.** The table's initial content transcribes what the Phase 5
through 12 records already state per row (met by, PARTIAL and
routed), and marks every Phase 13 row `open` until the Phase 13 exit
record flips it. Where a record did not walk a row (pillars A and D,
walked at Phases 1 and 4 before the row-by-row convention), the
status cites the phase's exit line and the drills by name, and the
plan's reviewer is the check. III.R (the autonomy end-state) is
`routed`, row by row, to the promotion evidence that measures it
(build plan §5), each note naming the measure and its owner: row 1
the dispatcher's re-triage rate and a human-review sample of draft
acceptance specs at the shadow run; row 2 `lanes.planner.unedited_rate`
above 0.800 and the receipts' independence on happy-path
submissions; row 3 the tiers' independence levels and the verifiers'
calibration agreement; row 4 every escalation packet's shape at the
shadow run; row 5 the shadow run itself, the five-bar ledger audit
applied to the real week; row 6 the report's flywheel and knowledge
sections and the cost per contract over the quarter after the
self-hosting cutover; row 7 the first external team's outcome at the
distribution step. A row flips to `met` when the promotion evidence
card records its measurement, so the pillar has a closure path and
`complete` becomes reachable exactly when the build plan's critical
path says it should: after the shadow run and the two cutovers, which
precede Phase 13's exit.

**D6. Bounds.** No admission change, no new verb, no projection: the
report is a document and a doctor section. `next/docs/generated/`
gains one file; the handbook gains one paragraph pointing at it.

## Acceptance Criteria

**Boundary set (new, shown working):**

1. **The table is the charter, row for row.** A row added to or
   removed from either side, or a text that differs, fails the drill.
2. **The vocabulary holds.** A status outside `met|partial|routed|open`,
   a `met` without evidence, a `partial` or `routed` without a note,
   fails validation and `docs generate` refuses.
3. **Rendered and drift-gated.** `conformance.md` renders
   deterministically from the table; a hand edit fails `docs check`.
4. **The doctor says what is not met.** `seed doctor` reports the
   counts, every row not met by pillar, row and status, and
   `complete` only when every row is met at an enforced posture; at
   the cooperative posture the enforced-only rows are reported as not
   applicable, the mixed rows are named, and `complete` is false with
   the reason.
5. **Mutation evidence.** Each fails a drill: a charter row dropped
   from the table; a status outside the vocabulary accepted; the
   rendering reading a clock; the doctor calling a table with an
   unmet row complete; an enforced-only row counted complete at the
   cooperative posture; a partial row counted as met; a mixed row set
   aside at the cooperative posture.
6. `make check` green with coverage measured cold, three readings
   above the gate; no model identifiers in any committed artifact.

**Retention set (existing, shown unharmed):**

- Every existing generated document renders byte-identically; the
  doctor's existing sections and refusals are unchanged; `docs check`
  on the committed tree is clean.
