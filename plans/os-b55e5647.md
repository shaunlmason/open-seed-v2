# os-b55e5647 — Phase 13 item 6: the machine-protocol surface and platform parity

Build plan Phase 13 item 6. Charter III.I row 3 ("The CLI is the
complete interface; the machine-protocol surface exposes identical
semantics; platform parity (including Windows) is documented and
tested") — the row the Phase 8 exit record routed here — and §II.10
("The CLI is the complete interface; a machine-protocol surface (e.g.
MCP) exposes the same verbs with identical semantics"). Deps: Phase 12.

## What the tree actually shows

- **Every verb already answers in one envelope.** `next/internal/envelope`
  renders `seed-envelope/0` — a result or a structured `{exit, code,
  message}` error, plus the affordances and the position stamp — and
  every CLI verb prints it (`envelope.OK`, `envelope.Fail`,
  `(*Envelope).Render`). The exit codes are the allocated table in
  `next/spec/envelope.md`.
- **The affordance list and admission share one rule set.**
  `admit.Affordances` drafts every catalog verb through the same
  `admit.Check` admission enforces (`affordanceCatalog` in
  `next/internal/admit/affordances.go`), so the envelope's "what is legal
  now" cannot drift from what the boundary permits (III.I rows 1 and
  2, met in Phase 8).
- **The CLI is a hand-written switch.** `next/cmd/seed/main.go` dispatches
  the top-level groups (`ledger`, `project`, `claim`, `verdict`,
  `merge`, `maintain`, `message`, `run`, `eval`, `knowledge`,
  `trajectory`, `doctor`, …) to per-group `run*` functions; there is no
  single table a second surface could read, so "the machine protocol
  exposes the same verbs" has nothing to derive from yet.
- **A machine transport exists for one narrow purpose.** Phase 12 item
  2's `seed-admit serve` answers signed-event *proposals* to the ledger
  ref over HTTP with the same rule set, refusals as envelopes. It is
  not a general verb surface: it carries proposal-shaped writes to one
  ref, not the read verbs (`situation`, `project current`, `lane
  show`), the local verbs (`plan lint`, `doctor`), or the artifact
  verbs.
- **No platform-parity statement exists.** The suites run on Linux CI
  only; nothing says what macOS or Windows can and cannot do, and
  nothing tests it. The one platform-shaped hazard already in the tree
  is the enforced self-hosted posture, whose `pre-receive` hook needs a
  server that runs it.

## Design decisions (binding for this task)

**D1. The machine protocol is JSON-RPC 2.0 over stdio: `seed serve`.**
One request-per-line JSON-RPC over stdin/stdout, a method per CLI verb
(`ledger.append`, `claim.take`, `situation.read`, …). Chosen over
extending item 2's HTTP service, which is scoped to signed proposals to
one ref: the machine surface must carry every read, write, local and
artifact verb, and stdio is credential-free (the caller passes the same
`--key`/`--ledger`/`--remote` inputs it would on the CLI, now as method
params) and needs no network, matching §II.10's "e.g. MCP" and v1's
`mcp serve` shape. Refused: a transport that reaches the ledger by any
path the CLI does not, or that holds a credential the CLI would not.

**D2. One command registry, two front-ends — the "exists iff" made
structural.** A `cmd/seed/registry` table registers every verb as
`{method, group, sub, run func(ctx) *envelope.Envelope}`. The CLI's
`next/cmd/seed/main.go` switch becomes iteration over the registry (the group's
subcommands dispatched from it), and `seed serve` dispatches a
JSON-RPC method to the same registry entry. The rule "a verb exists on
the protocol iff it exists on the CLI" is then a property of one table,
pinned by a drill that derives both surfaces' method sets from the
registry and asserts set equality — the III.I row 3 obligation made a
regression test, the shape the Phase 8 affordance-regression class
already uses. Refused: a second hand-maintained list of protocol
methods (it would drift, which is the whole failure the row forbids).

**D3. Identical semantics: the protocol calls the CLI's own run
functions and returns the CLI's own envelope.** A `seed serve` method
invocation runs the registry entry's `run` — the same function the CLI
calls — and returns the `seed-envelope/0` it produces verbatim in the
JSON-RPC `result`, with the envelope's `exit` and `code` preserved
(a refusal is a JSON-RPC result carrying the failing envelope, not a
transport-level JSON-RPC error, so a machine caller reads the same
structured code the CLI's exit status carries). The affordances and
the position stamp ride every response. Drilled by running a corpus of
verbs through both surfaces against one fixture ledger and asserting
byte-identical envelopes. Refused: re-deriving any result in the
protocol layer; a distinct error taxonomy for machine callers.

**D4. Platform parity is documented per platform and tested on a CI
matrix.** `next/spec/platform.md` states, per platform (Linux, macOS,
Windows): path handling (every filesystem path built with
`path/filepath`, never a literal `/`, audited by a lint that greps for
`"/"`-joined path construction outside URL and ref code); line endings
(the ledger's JCS bytes and every canonical form are LF, and the reader
tolerates neither CR injection nor `core.autocrlf` mangling — a drill
writes a segment with CRLF and asserts verification refuses rather than
silently normalizes); and the **honest capability list** — what a
platform cannot do and what posture it must therefore run. The
enforced self-hosted `pre-receive` hook needs a server that executes it
(a POSIX-style git host or a self-hosted server), so a bare Windows or
managed-forge checkout runs the cooperative or forge-hosted posture;
`seed doctor` reports the platform and names the postures available on
it. The CI matrix runs the Go suites on `ubuntu-latest`,
`macos-latest` and `windows-latest`. Refused: a parity claim with no
test; a silent `t.Skip` — every platform-gated skip names its reason.

**D5. The CLI stays the complete interface.** The protocol adds no verb
the CLI lacks and removes none; D2's set-equality drill enforces both
directions. `seed-envelope/0` is unchanged; the JSON-RPC framing is a
transport wrapper (`machine-envelope/0` if a versioned envelope around
the seed-envelope is needed), versioned independently so the verb
semantics never fork. Refused: a protocol-only verb; a protocol that
returns a shape `seed-envelope` cannot express.

**D6. Windows is tested, not asserted.** The matrix runs `go test
./...` on `windows-latest` and `macos-latest`, not only Linux; the
path lint and the CRLF drill run on each; the enforced-hook drills that
need a POSIX server skip on Windows **with a named reason** recorded in
the run and in `platform.md`, never silently. Refused: marking Windows
"supported" off a Linux-only run.

**D7. Scope bounds.** The machine surface is a transport over the
existing run functions: no new verb semantics, no envelope-schema
change beyond the optional transport wrapper, no admission change. The
`request.*` mirror arm and cross-repo ingress are Phase 13 item 4's
(III.J row 2), not this card. `seed-admit serve` (item 2) is unchanged;
`seed serve` is the general verb surface beside it, and `platform.md`
states how the two relate.

1. `next/cmd/seed/registry` (new): the verb registry `{method, group, sub,
   run}`; register every existing verb; rewrite `next/cmd/seed/main.go`'s dispatch to
   iterate it (behavior-preserving — every CLI drill stays green).
2. `next/cmd/seed/serve.go` (new): `seed serve`, JSON-RPC 2.0 over stdio,

## Acceptance Criteria

**Boundary set (new, shown working):**

1. **Exists iff.** The CLI's verb set and `seed serve`'s method set are
   both derived from the one registry and are equal; a verb added to
   one without the other fails the drill; a protocol-only or CLI-only
   verb is impossible by construction.
2. **Identical semantics.** For a corpus of read, write, refusing and
   local verbs run against one fixture ledger, the envelope from `seed
   serve` is byte-identical to the CLI's, exit code and affordances and
   position stamp included; a refusal carries the same `{exit, code,
   message}`.
3. **The CLI stays complete.** No verb exists on the protocol that the
   CLI lacks; `seed-envelope/0` is unchanged; the transport framing is
   versioned separately.
4. **Platform parity documented.** `platform.md` states path handling,
   line endings and the per-platform capability/posture list, including
   why the enforced self-hosted hook is unavailable where no server
   runs it; `seed doctor` reports the platform and its available
   postures.
5. **Platform parity tested.** The CI matrix runs the Go suites on
   Linux, macOS and Windows; the path lint and the CRLF-refusal drill
   pass on each; every platform-gated skip names its reason.
6. **Mutation evidence.** Each fails a drill: a protocol method not in
   the registry; a CLI verb not in the registry; the protocol
   re-deriving a result instead of calling the run function; a refusal
   returned as a JSON-RPC transport error rather than the failing
   envelope; a path built with a literal separator; a CRLF segment
   silently normalized instead of refused; a Windows skip without a
   reason.
7. `make check` green with coverage measured cold, three readings above
   the gate on Linux; the suites pass unprivileged.

**Retention set (existing, shown unharmed):**

- Every CLI verb behaves exactly as before (the group drills unchanged
  and green); `seed-envelope/0` is byte-identical on chains this card
  does not create; the exit-code table is unchanged.
- `seed-admit serve` (item 2) is untouched; no admission, transition,
  capability or protocol-version change; every pre-existing chain
  verifies byte for byte.
