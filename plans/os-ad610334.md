# os-ad610334 — Phase 13 item 3: a non-primary forge adapter for the forge extras

Build plan Phase 13 item 3: a non-primary forge adapter for the forge
extras (III.N). Charter §II.15 ("the core loop runs on any git remote
supporting the declared admission posture; forge extras — PR
observation, protections, identities — are adapters"), III.N row 2
("The core loop runs on any git remote supporting the declared
admission posture; at least one non-primary forge is supported by
adapters"). Deps: Phase 12.

## What the tree actually shows

- **The core loop is forge-neutral already.** Both enforced postures
  run over any git remote (`next/spec/postures.md`: the pre-receive
  hook and the proposal service, one rule set); `merge.observed` is
  the observer's forge fact `{merged, pr}` with no forge in it; the
  ledger ref is a branch under the forge-hosted posture because forges
  protect branches, not refs.
- **The forge extras are behind one interface, with one real
  adapter.** `internal/protections.Forge` (`Read`, `Apply`) over a
  forge-neutral desired state (`Desired`: the four rulesets — the
  ledger branch updatable by the admission identity alone, the
  default branch requiring the declared checks and reviews, contract
  branches protected from force-push and deletion, release tags
  immutable — with `Unexpressible` for what a forge cannot say);
  `GitHub` (rulesets over the REST API) and `Snapshot` (the
  credential-free JSON arm CI runs) implement it; `seed protections
  plan|apply --forge snapshot|github`.
- **GitHub-shaped places outside the adapter** are naming and
  comments: the admission block's `identity` is a forge login, the
  `token-env` default is `GITHUB_TOKEN`, the handbook and
  `postures.md` speak of rulesets and CODEOWNERS; the compromised-actor
  drill and the release gate (Phase 12 item 1) run `make check` and
  the protections reconcile, which is the reconciler above.
- **No forge is declared.** The declaration says the posture and the
  admission endpoint; which forge hosts the repository is implicit in
  the `--forge` flag a human passes.

## Design decisions (binding for this task)

**D1. The second forge is Forgejo (Gitea-compatible).** Self-hostable,
the natural non-primary forge for a project whose own posture is
self-hosting, with a small stable REST API whose branch-protection
and tag-protection resources express the four rulesets. Chosen over
GitLab, whose protected-branch and merge-request models differ from
both GitHub's and the desired state's in more places, which would
widen `Unexpressible` for no gain here. Refused: a third adapter in
this card; a forge whose API the drill cannot fake faithfully.

**D2. One adapter, the same interface, the same decision table.**
`internal/protections/forgejo.go` implements `Forge` over Forgejo's
API: `Read` lists branch protections and tag protections and maps
them into `State` (rulesets by the four names, the default branch
from the repository, and `Unexpressible` naming what Forgejo cannot
say — a bypass list beyond the push whitelist, conversation
resolution); `Apply` creates, updates and deletes protections so that
a following `Read` matches `Desired`. The mapping is a table in the
adapter (ruleset → protection fields: the ledger branch's push
whitelist is the admission identity alone with force-push and
deletion blocked; the default branch's required status contexts,
required approvals and stale-approval dismissal; contract branches by
glob; release tags protected from update and deletion). `Desired` is
untouched: one decision table, two forges held to it. Refused: a
forge-specific desired state; a Forgejo rule the table does not
derive.

**D3. The declaration names the forge.** The `admission` block gains
`forge: "github" | "forgejo"` (absent means `github`, so every
existing declaration keeps its meaning) and `api: "<base url>"`
(absent means the forge's public API, which Forgejo has none of, so a
Forgejo declaration names its instance). `seed protections
plan|apply` reads the forge from the declaration when `--forge` is
not given, keeps `--forge snapshot` as the credential-free arm, and
takes the token from `--token-env` (default `GITHUB_TOKEN` for GitHub,
`FORGEJO_TOKEN` for Forgejo). The doctor reports the declared forge.
Refused: a token in the declaration; a forge the build has no adapter
for.

**D4. The observer's merge facts stay forge-neutral, and each forge
supplies them.** `merge.observed`'s `{merged, pr}` is unchanged. An
`Observer` interface in `internal/protections` (`Merged(pr string)
(sha string, merged bool, err error)`) reads a pull request's merge
state — GitHub (`/pulls/{n}`) and Forgejo (`/repos/{o}/{r}/pulls/{n}`
carry `merged` and `merge_commit_sha` alike) — and `seed merge
observe` gains `--forge`/`--pr` to fill `merged` from the forge when
the caller does not pass it, refusing when the PR is not merged. The
snapshot arm answers from the snapshot file. Refused: a forge-shaped
field in the ledger fact; an observer that writes.

**D5. The release gate is the same gate on both forges.** The
compromised-actor drill and the release gate (`make check`, the
protections reconcile under the enforced posture) run through the
reconciler; the drill that holds the forge's protections to the
desired state runs over `{snapshot, github, forgejo}` against
in-process fakes of each API — a fake Forgejo server faithful to the
endpoints the adapter uses (branch protections, tag protections, the
repository, pull requests), with the drill asserting plan → apply →
read → no drift, unexpressible rules reported, and the ledger branch's
sole writer the admission identity on each. Refused: a live-forge
drill as the only evidence; a fake that answers what the adapter does
not ask.

**D6. Credential-free CI, live drills opt-in.** CI runs the fakes; a
live Forgejo drill runs when `SEED_FORGEJO_URL`, `SEED_FORGEJO_REPO`
and `FORGEJO_TOKEN` are set and skips with the reason named when not
(`platform.md`'s skip rule). Refused: a silent skip; a secret in the
tree.

**D7. The per-forge page.** `next/spec/forges.md` (new) is the
per-forge capability table: for GitHub and Forgejo, how each of the
four rulesets is expressed, what is unexpressible and what the
deployment must do by hand for it, the identity model (a forge login
as the admission identity), the token env var, and the observer's
source of merge facts. The operator handbook (Phase 12 item 6) links
it as its forges page. Refused: a claim on the page a drill does not
back.

**D8. Bounds.** No admission, transition or ledger-verb change; the
GitHub adapter's behavior is unchanged (its drills green); the hook
and the proposal service are untouched; identities stay forge logins
in the admission block.

## Acceptance Criteria

**Boundary set (new, shown working):**

1. **A second forge is supported by adapters.** `seed protections
   plan|apply --forge forgejo` reconciles a Forgejo repository to the
   same desired state GitHub is held to; `Read` after `Apply` shows no
   drift; what Forgejo cannot express is reported, never dropped.
2. **One decision table.** `Desired` is unchanged and both adapters
   are drilled against it with the snapshot arm beside them.
3. **The forge is declared.** `admission.forge` and `admission.api`
   are strict, default to GitHub, and drive the CLI and the doctor.
4. **Merge facts from either forge.** `seed merge observe --forge
   --pr` fills `{merged, pr}` from GitHub or Forgejo and refuses an
   unmerged PR; the ledger fact is unchanged.
5. **Credential-free CI.** Every drill runs against fakes; the live
   drill is opt-in with a named skip.
6. **The per-forge page.** `forges.md` states the capability table for
   both forges with every claim drilled.
7. **Mutation evidence.** Each fails a drill: a Forgejo mapping that
   drops the ledger branch's push whitelist; an unexpressible rule
   dropped silently; a token in the declaration; an observer that
   reports an unmerged PR as merged; the desired state forked per
   forge; a live-drill skip without a reason.
8. `make check` green with coverage measured cold, three readings
   above the gate; no model identifiers in any committed artifact.

**Retention set (existing, shown unharmed):**

- The GitHub adapter's drills are green and its requests unchanged;
  every existing declaration parses with the same meaning (`forge`
  absent is GitHub); `merge.observed` admits exactly as before; the
  compromised-actor drill and the release gate are unchanged.
