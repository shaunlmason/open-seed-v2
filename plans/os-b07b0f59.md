# Plan: next Phase 5.3 — four-part handoff packets (os-b07b0f59)

Implements [`docs/next-build-plan.md`](../docs/next-build-plan.md) Phase 5
item 3: "Four-part packets (acceptance criteria; verified/asserted
decisions; commit-anchored refs incl. diff-vs-merge-base range;
investigation findings) — schema, size bound, lint; written on
release/park/reap." Design authority: [`SEED-NEXT.md`](../SEED-NEXT.md)
Part II §6 "Handoff packets (normative)" (the packet is the *only*
interface between executors; four bounded, mechanical parts; unmarked
assertions shield upstream errors; bare paths assume a filesystem
disposable executors don't have; findings are the negative knowledge a
successor must not rediscover) and conformance III.F: "Every exit from
in_progress is deliberate; every involuntary exit leaves a packet;
silent abandonment is impossible" and "Packets contain exactly four
bounded parts … shape-linted and size-bounded" and "Packet sufficiency
is drilled: a fresh executor completes a killed executor's contract
from the packet alone, including not re-trying recorded dead ends."
Deps: 5.1 (#113) and 5.2 (#114) plans; implementation stacks on 5.2's
branch once the chain exists.

## Design decisions (binding for this task)

- **Which exits carry packets — all of them**: `submission.made`,
  `claim.released`, `claim.parked`, and `claim.reaped` payloads MUST
  carry a packet (review finding on #115: the charter's "written on
  every deliberate exit and every reap" includes submit, and the
  narrower build-plan item cannot override it — a submission that
  fails verification returns the contract to the pool, and the
  packet is what the next executor resumes from). `submission.made`
  carries the packet alongside its verifier-specific fields (branch,
  evidence refs, per the catalog), which Phase 6 hardens; the
  reaper writes the reap packet from what is known (§"Preemption":
  force-kill still yields one). III.F's involuntary-exit row and the
  charter's every-deliberate-exit sentence are both satisfied.
- **Inline v0, ref form named**: the packet is inline JSON under a
  `"packet"` payload key, canonical size ≤ **3072 bytes** — a bound
  chosen to FIT the landed Phase 1.6 whole-payload cap
  (`max_payload_bytes: 4096`) with room for the wrapper and the
  verb's sibling fields (review finding on #115: an 8 KiB packet
  could never admit). Packets are bounded findings, never
  transcripts — an escalation is "one packet, one question, one
  decision", never a log — and the arithmetic is stated in the spec.
  The artifact-store reference form (`packet_ref`) is a named
  extension point that lands with the artifact store (sealed-check
  infrastructure, Phase 6); the schema reserves the key now so the
  migration adds a branch, not a reshape.
- **The schema (v1, exactly four parts, all keys required)**:
  1. `acceptance`: non-empty array of strings — a packet a successor
     cannot be judged against resumes nothing.
  2. `decisions`: array of `{decision, basis}` with `basis` ∈
     {`verified`, `asserted`} — the marking is structural, so an
     unmarked assertion is a shape violation, not a shield.
  3. `base` and `refs`: `base` is a REQUIRED range string
     `"<merge-base>..<head>"` — the resume coordinate, distinct from
     the artifacts — with the no-work case the unambiguous
     zero-length range `"<merge-base>..<merge-base>"` (review
     finding on #115: the entry union could not represent a lone
     merge-base), so the diff-vs-merge-base is always derivable;
     `refs` is an array of **combined anchored strings** in the
     charter's own forms — `"path @ commit"` or `"ref @ range"` —
     which the Phase 1.6 classifier already exempts from the
     free-text budget (review finding on #115: split
     `{path, commit}` objects would have every path and sha counted
     against the 1024-byte aggregate). `refs` may be empty (`base`
     carries the coordinate); bare unanchored paths refuse. If the
     bare-range `base` form falls outside the classifier's existing
     reference exemption, the exemption's pattern data extends to
     cover it (a classifier data change, drilled in the hostile
     corpus) — scoped here so the packet never spends its prose
     budget on anchors.
  4. `findings`: array of `{tried, outcome, pointer?}` — the
     negative knowledge; may be empty (a trivial park has nothing to
     record and says so with an empty array, honestly), but the key
     is never absent.
  Unknown keys refuse (strict shape, the wire-parsing precedent).
  The free-text fields (`decision`, `tried`, `outcome`,
  `acceptance` entries) fall under the Phase 1.6 classification
  lint's aggregate free-text budget — packets are data, never
  instructions, and the hostile corpus extends to packet fields.
- **Admission wiring**: the packet check joins the payload-shape
  stage for the four exit verbs (after fence, with the lifecycle
  rule's transition check — a shape-invalid packet refuses before the
  transition applies), typed `PacketError{Subject, Part, Reason}`
  mapping to the existing shape-refusal exits: structural violations
  refuse as invalid payload shape; free-text budget violations keep
  exit 9 `classification`. **No new exit codes.**
- **The resume drill is mechanical, not narrative** (Phase 5 exit
  criterion): executor A is a scripted harness that claims, records
  one verified decision, one asserted decision, one dead end
  (`tried: approach-X, outcome: fails because …`), pushes a commit,
  and is force-reaped with a packet; executor B is a deterministic
  function **whose only input is the packet** (no transcript, no
  workspace reuse — a fresh clone at the packet's merge-base anchor):
  B resumes, completes the acceptance list, and the drill asserts
  B's action log never contains approach-X and that B's fresh clone
  plus the packet's refs reproduce A's artifacts. Sufficiency is the
  assertion, not a vibe.
- **Escalation packets** (`blocked(needs-you)` carrying packet +
  question + minimal decision) belong to the routing/escalation
  phase (§7 lands with dependencies/routing); the schema they will
  reuse is this one, stated as a forward pointer.

## Steps

1. **The packet package** (`next/internal/packet`): schema types,
   strict `Parse`/`Validate` (four parts, basis vocabulary,
   commit-anchor forms, the merge-base-anchor requirement, the size
   bound on canonical bytes, unknown-key refusal), and
   `Lint(records)`-style helpers the admission rule and drills
   share; typed `PacketError{Subject, Part, Reason}`.
2. **Admission wiring** (`internal/admit` + envelope mapping): the
   four exit verbs require a shape-valid packet; classification
   budgets extend over packet free text; refusal mapping as above.
3. **Spec** (`next/spec/packets.md`, new): the four parts verbatim
   from the charter with the schema, the size bound and its
   rationale, the inline-v0/ref-form split, the
   submission verb's dual payload (packet beside verifier fields),
   the classification posture
   (packets are data), and the conformance mapping; `lifecycle.md`
   cross-references the exit verbs' packet obligation.
4. **Drills**:
   - *Shape*: each part missing, an unmarked decision, a bare path,
     a missing merge-base anchor, an unknown key, and an oversize
     packet each refuse with the part named; a minimal honest packet
     (empty findings, empty refs, zero-length base) admits.
   - *Exit coverage*: all four deliberate exits and reap without a
     packet refuse; with valid packets they admit and land per the
     table; submission.made admits carrying the packet alongside its
     verifier fields under the whole-payload cap; a zero-length
     `base` range (no work pushed) admits and resumes.
   - *Classification*: hostile-corpus rows extend to packet fields
     (imperative text over budget refuses 9); a refs-heavy packet
     with many combined anchors passes — anchors never spend the
     prose budget.
   - *Packet resume* (the Phase 5 exit drill): the A/B fixture above
     — B completes from the packet alone in a fresh clone, never
     re-tries the recorded dead end, and reproduces A's artifacts
     from the commit anchors.
   - *Tolerant history*: a raw-pushed packetless release verifies
     (admission policy) and surfaces in the contracts view's
     anomalies count.

## Acceptance Criteria

**Boundary set (new, shown working):**

- The packet schema enforces exactly four parts with structural
  verified/asserted marking, combined-string anchors with a
  mandatory `base` range (zero-length for no work), strict keys, and
  the 3072-byte bound that fits the landed payload cap; every
  planted violation refuses naming the offending part.
- All four deliberate exits and reap refuse without a valid packet
  and admit with one, `submission.made` included (packet beside its
  verifier fields, under the whole-payload cap); raw-pushed
  packetless history verifies and surfaces as anomalies.
- Packet free text sits under the classification budget with
  hostile-corpus coverage.
- The resume drill passes mechanically: B, given only the packet and
  a fresh clone at its anchors, completes the acceptance list,
  reproduces A's artifacts, and never re-tries the recorded dead
  end.

**Retention set (existing, shown unharmed):**

- All existing verb suites pass unchanged
  (`cd next && go test ./internal/... ./cmd/... -count=1`).
- The repo-wide gate stays green with the ≥90% coverage gate
  (`make check`).
